# 页面内语音控制设计

## 目标

用户在 AI 教学页面点击“开启语音控制”后，不打开弹窗，浏览器直接开始持续监听。语音被识别并解析成指令后，页面立即执行对应的视频控制。例如用户说“慢一点”，当前参考视频立即降低播放速度。

## 交互设计

### 未开启

- 页面只显示“开启语音控制”主按钮。
- 点击按钮后申请麦克风权限并启动持续语音识别。
- 不打开对话框，不离开或遮挡当前教学页面。

### 监听中

- 主按钮文案变为“正在持续监听”，用于清晰展示当前状态。
- 主按钮旁显示独立的“关闭”按钮。
- “正在持续监听”按钮不承担关闭功能，避免误触中断。
- 页面内展示识别中的临时文字以及最近一次指令反馈。

### 关闭

- 点击“关闭”后立即停止浏览器语音识别和自动重启逻辑。
- 清空识别中的临时文字。
- 界面恢复为只有“开启语音控制”按钮的初始状态。

## 指令数据流

1. `VoiceControlPanel` 启动 `useBrowserSpeechRecognition`。
2. 浏览器 Web Speech API 产生最终转写文本。
3. 前端将文本提交到现有 `/api/voice/commands/interpret` 接口。
4. 接口返回结构化语音意图。
5. `VoiceControlPanel` 通过现有 `onCommandRecognized` 回调将结果交给 AI 教学运行时。
6. `useTeachingRuntime.handleVoiceResult` 立即操作当前参考视频或发送教学 Agent 事件。

现有指令映射保持不变，包括慢一点、快一点、指定倍速、暂停、继续、上一动作、下一动作和重新开始等。

## 组件改动

### `VoiceControlPanel`

- 删除控制语音交互的 `Dialog` 及其开关状态。
- 将开启按钮改为直接调用 `startListening`。
- 监听期间以内联布局显示状态按钮、关闭按钮、临时转写和最近结果。
- 保留错误提示，但改为页面内反馈或现有 `Snackbar`，不依赖弹窗。
- 移除仅为弹窗文字测试而存在的输入框、示例标签和相关状态，以保持主页面简洁。

### `useBrowserSpeechRecognition`

- 保持持续监听、结束后自动重启、重复文本抑制及错误处理行为。
- 关闭时继续使用现有 `stopListening`，确保不会在识别结束后自动重启。

### `useTeachingRuntime`

- 保持现有指令执行路径。
- “慢一点”继续直接把视频播放速度设为 `0.5`；指定倍速限制在 `0.25` 至 `2` 之间。
- 本次不修改后端语音解析协议。

## 错误和边界处理

- 浏览器不支持 Web Speech API 时，禁用开启按钮并在页面内提示使用最新版 Chrome 或 Edge。
- 麦克风权限被拒绝、找不到麦克风或识别服务不可用时，停止监听状态并显示错误。
- 后端解析失败时保留监听，只提示本次指令解析失败，用户可以继续说下一条指令。
- 连续识别到相同的临时和最终文本时，沿用去重逻辑，避免同一指令执行两次。
- 组件卸载时终止识别并清理重启定时器。

## 测试策略

- 组件测试：初始状态只出现开启按钮且没有弹窗。
- 组件测试：点击开启后调用启动识别，监听状态显示“正在持续监听”和“关闭”。
- 组件测试：点击关闭后调用停止识别并恢复初始界面。
- 组件测试：最终转写经解析后触发 `onCommandRecognized`。
- 运行时测试：“慢一点”将视频播放速度设置为 `0.5`。
- 回归验证：前端 lint、相关测试和生产构建全部通过。

## 不在本次范围内

- 替换浏览器 Web Speech API。
- 修改后端 Kimi 或规则指令解析。
- 增加唤醒词、声纹识别或服务端音频流。
- 调整 AI 教学页面的其他视觉模块和业务流程。
