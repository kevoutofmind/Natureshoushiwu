# 语音控制诊断设计

## 目标

让语音控制链路可以区分三类问题：

1. 浏览器是否识别到语音。
2. 识别文本是否匹配到语音指令。
3. 已匹配指令是否实际作用于视频或教学运行时。

教学界面只展示识别文字。关键词匹配和执行结果仅写入浏览器开发者控制台，避免增加普通用户看到的诊断信息。

## 界面

语音控制开启后，在现有内联控制区域展示“识别文字”：

- 识别过程中显示浏览器返回的临时转写。
- 识别完成后保留最近一次最终转写。
- 尚未识别到内容时显示简短提示。
- 关闭语音控制时清除临时转写；最近一次最终转写沿用现有界面状态。

不在界面展示关键词、意图、置信度或视频执行结果。

## 调试日志

每次提交的最终转写生成一个递增的诊断标识，并通过现有回调链路传递。浏览器控制台使用统一的 `[Voice]` 前缀输出三类结构化日志：

- `[Voice] recognized`：诊断标识和最终识别文本。
- `[Voice] matched`：诊断标识、是否接受、匹配到的 intent、参数和置信度。
- `[Voice] executed`：诊断标识、执行目标、执行结果以及可验证的执行后状态。

未匹配到关键词时仍输出 `matched`，其中 `accepted` 为 `false`、`intent` 为 `null`，且不会输出成功的执行日志。解析请求失败时输出 `[Voice] match-error`。

## 执行验证

视频本地指令在赋值或调用后记录实际状态：

- 调速指令记录 `video.playbackRate`。
- 暂停或继续播放记录教学运行时的分发结果；异步执行失败记录错误。
- 找不到视频元素或缺少参数时记录 `executed` 失败原因。
- 交给教学 Agent 的指令记录映射后的命令和异步调用结果。

日志只用于开发调试，不改变后端协议，也不把调试状态持久化。

## 代码范围

- `VoiceControlPanel`：展示识别文字，生成诊断标识，记录识别及匹配日志。
- `VoiceCommandResult` 的前端处理链路：携带可选诊断标识，不修改服务端响应。
- `useTeachingRuntime.handleVoiceResult`：记录指令执行结果。

保留当前工作区中已完成的页面内语音控制改动，不恢复弹窗和文字测试输入框。

## 测试

前端当前没有组件测试框架，因此把可独立验证的日志数据构造和执行结果描述提取为纯函数，并用 TypeScript 类型检查、ESLint 和生产构建覆盖集成风险。运行时再通过浏览器控制台手动验证一条匹配指令和一条未匹配文本。

## 不在范围内

- 在界面展示匹配或执行诊断。
- 修改后端关键词规则或 Kimi 路由。
- 保存语音历史。
- 替换 Web Speech API。
